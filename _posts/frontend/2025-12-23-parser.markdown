현재 개발 중인 서비스에는 핵심적인 요구사항이 하나 있습니다. 바로 **"PDF 파일의 내용을 추출하여 DB에 저장하고, 이를 웹에서 보여준 뒤 사용자가 편집할 수 있어야 한다"**는 것입니다.

이 과정에서 우리는 데이터 저장 포맷으로 **Markdown**을 선택했습니다. HTML 통째로 DB에 저장하기에는 불필요한 태그가 너무 많아 무겁고, 순수 텍스트만 저장하기에는 서식 정보가 사라지기 때문입니다.

따라서 프론트엔드단에서는 다음과 같은 **양방향 변환 흐름**이 필요했습니다.

1.  **Read (DB → View):** DB에 저장된 마크다운을 가져와 HTML로 변환하여 렌더링
2.  **Write (Edit → DB):** 사용자가 웹 에디터(HTML)에서 수정한 내용을 다시 마크다운으로 변환하여 저장

오늘은 `unified` 생태계를 활용해 이 순환 구조를 어떻게 구현했는지 공유합니다.


## 1. Architecture: 데이터의 여행

데이터는 다음과 같은 흐름으로 변환됩니다. PDF 파싱 단계에서 추출된 텍스트는 1차적으로 마크다운 형태로 DB에 적재되어 있습니다.

* **조회 시:** `DB (Markdown)` → `Frontend Parser` → `Web View (HTML)`
* **저장 시:** `Web Editor (HTML)` → `Frontend Parser` → `DB (Markdown)`

이 양방향 통신을 위해 `unified`, `remark`(마크다운 처리), `rehype`(HTML 처리) 라이브러리를 조합하여 유틸리티를 구성했습니다.

## 2. Viewer 구현: Markdown to HTML

DB에서 꺼내온 마크다운 텍스트를 브라우저에 보여주는 단계입니다. 단순 변환만 하면 될 것 같지만, PDF에서 추출된 텍스트는 종종 들여쓰기나 특수문자가 엉켜 있는 경우가 많아 **전처리(Pre-processing)**가 필수적이었습니다.

### 🛠️ 커스텀 전처리 전략

PDF 파싱 데이터 특성상 인용구(`>`) 포맷이 불규칙하게 들어오는 경우가 있었습니다. 이를 `unified` 파이프라인에 태우기 전에 정규식과 문자열 조작으로 깔끔하게 정리해 주는 과정을 먼저 거쳤습니다.

```javascript
export const convertMarkdownToHtml = (markDownText) => {
  if (!markDownText) return '';

  // 1. PDF 데이터 클렌징: 불필요한 백슬래시 제거
  const cleanedText = markDownText.replace(/\\/g, '');

  // 2. 인용문 구조 정규화: > 문법을 감지하여 강제로 <blockquote> 태그 입히기
  // (PDF에서 줄바꿈이 깨져서 오는 인용문들을 올바르게 렌더링하기 위함)
  const processQuotes = (text) => {
    const lines = text.split('\n');
    let inQuote = false;
    let result = '';
    let quoteContent = '';

    for (let i = 0; i < lines.length; i++) {
      const line = lines[i];
      if (line.trim().startsWith('>')) {
        // 인용문 시작 또는 계속
        inQuote = true;
        quoteContent = '';
        quoteContent += line.replace(/^>\s*/, '') + '\n'
      } else {
        // 인용문이 끝남
        if (inQuote) {
          result += `<blockquote><p>${quoteContent}</p></blockquote>\n`;
          inQuote = false;
        }
        result += line + '\n';
      }
    }

    // 마지막 인용문 처리
    if (inQuote) {
      result += `<blockquote><p>${quoteContent}</p></blockquote>\n`;
    }

    return result;
  };

  const processedText = processQuotes(cleanedText);

  // 3. Unified 파이프라인 실행
  const result = unified()
    .use(markdown) // MD 파싱
    .use(remarkGfm, { singleTilde: false }) // 테이블, 취소선 등 지원
    .use(remark2rehype, { allowDangerousHtml: true }) // 전처리된 HTML 태그 허용
    .use(rehypePrismPlus) // 코드 블럭 하이라이팅
    .use(rehypeExternalLinks)
    .use(html, { allowDangerousHtml: true })
    .processSync(processedText);

  return result.value;
}
```

이 과정을 거치면 PDF에서 갓 추출된 거친 마크다운 데이터가 웹에서 보기 좋은 깔끔한 HTML로 렌더링 됩니다.

## 3. Editor 구현: HTML to Markdown

사용자가 브라우저 상의 에디터(ContentEditable 영역 등)에서 오타를 수정하거나 내용을 추가하면, 그 결과물은 **HTML** 형태가 됩니다. 이를 다시 DB에 넣을 때는 규칙성을 가진 **Markdown**으로 되돌려야 합니다.

이때는 `rehype-parse`(HTML 읽기)와 `rehype2remark`(마크다운으로 변환) 플러그인을 사용하여 역방향 파이프라인을 구축했습니다.

```javascript
export const convertHtmlToMarkdown = async (htmlText) => {
  const result = await unified()
    .use(rehypeParse, { fragment: true }) // HTML 조각 파싱
    .use(rehype2remark) // 핵심: HTML AST를 Markdown AST로 변환
    .use(remarkGfm, { singleTilde: false }) // GFM 문법 유지
    .use(remarkStringify, {
      fences: true, // 코드 블럭은 ``` 사용
      bullet: '-',  // 리스트는 - 사용
    })
    .process(htmlText)

  return result.value
}
```

이렇게 하면 사용자가 `<b>굵게</b>` 처리한 텍스트는 DB에 `**굵게**`로, `<ul><li>목록</li></ul>`은 `- 목록`으로 깔끔하게 변환되어 저장됩니다.

## 4. 엣지 케이스 핸들링 (Date & Entities)

서비스 운영상 필요한 날짜 포맷팅과 특수문자 처리도 유틸리티에 포함했습니다.

* **Timezone 이슈:** 서버 데이터(UTC)를 한국 사용자에 맞게 보여주기 위해 KST(+9시간) 오프셋을 직접 계산하여 적용했습니다.
* **HTML Entity:** PDF 추출 과정이나 에디터에서 발생할 수 있는 `&nbsp;`, `&lt;` 등의 엔티티 코드를 원래 문자로 복원하는 `unescape` 로직을 추가하여 데이터 무결성을 높였습니다.

```javascript
// KST 시간 보정 및 포맷팅
export const formatDate = (dateStr, type = null) => {
  const date = new Date(dateStr)
  const TIME_ZONE = 9 * 60 * 60 * 1000 // 9시간 (KST)
  
  if (Object.prototype.toString.call(date) !== '[object Date]' || isNaN(date)) {
    return ''
  }

  if (type === 'yyyy-mm-dd') {
    return new Date(date.getTime() + TIME_ZONE)
        .toISOString()
        .replace('T', ' ')
        .slice(0, -5)
  }
  // ... (기타 포맷 처리)
}
```

## 📝 마치며

결국 이 파서는 **"PDF의 정적인 데이터"**를 **"웹의 동적인 데이터"**로 연결해 주는 다리 역할을 합니다.

* **DB 저장 효율:** 마크다운으로 저장하여 용량 최적화
* **사용자 경험:** HTML로 렌더링하여 위지윅(WYSIWYG) 편집 환경 제공

`unified` 생태계를 활용하면 단순히 포맷을 바꾸는 것을 넘어, 우리 서비스의 데이터 특성(PDF 파싱 데이터)에 맞는 커스텀 전처리 로직을 유연하게 끼워 넣을 수 있어 매우 효과적이었습니다.
